## Library

**Стек**
- .NET 8
- Entity Framework + PostgreSQL
- xUnit
- .NET Aspire
- Bogus
- RabbitMQ
- Blazor
  
**Информация о запуске**
При запуске AppHost приложение автоматически поднимает контейнер для БД, миграции применяются в `Api` после подключения, строка подключения создается и передается в `Api` через Aspire. Для запуска необходим запущенный Docker.
Для запуска RabbitMQ необходимо ввести данные пользователя на панели ресурсов Aspire, эти данные используются для входа на соответствующий dashboard.

#### Domain
- **Entities** — сущности предметной области:
  - `Book` — карточка книги
  - `BorrowRecord` — запись о выдаче книги
  - `Customer` — читатель библиотеки
- **Enums** — перечисления, используемые в карточках книг:
  - `Publisher` — издательства
  - `PublishingType` — типы изданий
- **Interfaces** — абстракции для репозиториев, которые реализуются в `Infrastructure`
- **DataSeeders** — подготовленные данные, для использования в тестах и начального заполнения в БД.

#### Infrastructure
- **Repositories** — Реализации интерфейсов из `Domain`:
  - `BookRepository` — карточка книги
  - `BorrowRecordRepository` — запись о выдаче книги
  - `CustomerRepository` — читатель библиотеки
- **Persistence** — Средства для подключения и настройки БД:
  - `Migrations` — Миграции для БД
  - `AppDbContext` — Контекст БД и настройка полей в таблицах
  - `DbSeeder` — Заполнение БД начальными данными из `Domain.DataSeeders`
- **Migrations** — Миграции для БД, применяются автоматически в `Api`.

#### Application
- **Services** — Сервисы с методами для работы с приложением:
  - `AnalyticsService` — Сервис с методами для получения аналитических данных о библиотеке.

#### Application.Contracts
- **Mappers** — Мапперы для DTO и сущностей из `Domain.Entities`:
  - `AppMappingProfile` — Профиль для автомаппера.
- **Dtos** — DTO, используемые в сервисах и для работы API:
  - `AnalyticsDtos` — DTO, используемые в сервисе для возврата аналитической информации
  - `BookDtos` — DTO карточки книги, с дополнительной информацией, для создания и редактирования объектов
  - `BorrowRecordDtos` — DTO записи о выдаче книги, с дополнительной информацией, для создания и редактирования объектов
  - `CustomerDtos` — DTO читателя, с дополнительной информацией, для создания и редактирования объектов.

#### Api
- **Controllers** — Контроллеры для работы с API:
  - `BookController` — контроллер для работы с карточками книг
  - `BorrowRecordController` — контроллер для работы записями выданных книг
  - `CustomerController` — контроллер для работы с записями о читателях
  - `AnalyticsController` — контроллер для получения аналитических данных о библиотеке, использует `AnalyticsService`
- `Program` - Конфигурация для приложения, настройка DI, регистрация сервисов.

#### Tests
- `DomainTests` — Юнит-тесты для `Domain`
- `TestDataFixture` — Вспомогательный класс для инициализации данных.

#### AppHost
- `Program` - Отвечает за запуск приложения с помощью Aspire, настройка зависимостей разных модулей и создание контейнеров.

#### DataGenerator
- `BogusGenerator` - Генератор на основе Bogus для создания контрактов для книг, пользователей и записей выданных книг.

#### RabbitMQ
- Содержит два проекта - Producer и Consumer, запускаются как Background сервисы, конфигурируются в `AppHost`.
- **Producer** - Использует `DataGenerator` для генерации контрактов и отправляет их по подключенному каналу, по умолчанию отправляет рандомный контракт каждую 0.1 секунды.
- **Consumer** - Принимает контракты по покдлюченному каналу, десериализует и сохраняет в бд.
  
#### Client(Blazor)
- Клиентское приложение, которое взаимодействует с сервером через API, на клиенте реализовано взаимодействие с приложением через соответствующие страницы и сервисы
- **Components** - Компоненты, используемые в приложении: книги, клиенты, записи и дополнительные
- **Layout** - Основной layout для страниц, содержит секции header, body и footer
- **Pages** - Страницы, используемые в приложении, используют `Components` и `Services`
- **Services** - Сервисы, которые позволяют обращаться к серверу и проводить операции уже в клиентской части
- **wwwroot** - Наборы стилей и ресурсов, используемых в приложении
- `App.razor` - Общая настройка для разметки
- `Program.cs` - Конфигурация приложения, настройка DI, регистрация сервисов.

#### Взаимодействие Клиента и Сервера
На сервере реализована система разграничения доступа с помощью Identity и JWT, при получении запросов с клиента, сервер идентифицирует пользователя, определяет его роль и возвращает только доступные ему ресурсы. Основная сущность учетной записи - `ApplicationUser` (находится в `Domain`), обычные пользователи имеют CustomerId, который привязыватся в этом классе, у админов привязки к пользователю нет. Для предоставления необходимого доступа и возможности авторизоваться, на сервере были изменены существующие контроллеры и добавлен дополнительный - `AuthController`.
Клиент, при регистрации или авторизации получает от сервера JWT токен, который добавляется в LocalStorage, с его использованием проводятся запросы на сервер. При выходе из аккаунта, токен удаляется.
Не авторизованный пользователь имеет доступ к основной странице и разделу /books, где может просматривать информацию о книгах.
Авторизованный пользователь может бронировать книги, создавая записи, а также просматривать свои уже созданные записи в разделе /records, менять свою личную информацию в разделе /profile.
Админ имеет доступ ко всем разделам + к разделу /customers, во всех разделах может добавлять/менять/удалять данные.
Помимо CRUD операций, во всех доступных разделах есть фильтрация и/или сортирока.
